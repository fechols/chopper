# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Chopper is a helicopter game for the 64 MHz C64 Ultimate (C64U) with a 16 MiB REU: a "mode 7" ground
floor (one REU DMA per bitmap byte) with streamed flat-shaded 3D objects, a HUD, AI, combat and sound on
four SIDs. `docs/design.md` is the game and engine design (keep it current when behaviour changes);
`docs/validation.md` the measured results; `docs/memory.md` is generated by `tools/memmap.py`.

## Architecture: one core, two machines, byte-exact

- **`src/` is one crate built twice.** With the `host` feature (default) it is the PC model and tools
  (`src/main.rs`: `chopper bake | frame | agent | map | flight | ...`, see its module doc). Without it
  the core modules are `no_std` and compiled by rust-mos into the C64 program (`target-c64/`, a separate
  cargo project whose `src/main.rs` is the frame loop). Host-only modules are `#[cfg(feature = "host")]`
  in `src/lib.rs`.
- **`hw::Hw`** (`peek`, `poke`, `reu_exec`) is the only machine access. The C64 implements it with
  volatile MMIO; the host with `model::Machine`. Shared code therefore runs identically on both, and the
  host renders every frame byte for byte as the C64 does.
- **The gate:** `tools/emu.py` runs `dist/chopper.prg` in a Python 6502 interpreter (`tools/native_cpu.py`,
  with an REU, raster IRQ and CIA timers) and compares each shown frame against `target/release/chopper
  frame`. Any change to shared code, asm or layout must keep **0 mismatched bytes**.
- **Hot paths are 6502 asm** in `target-c64/asm/*.S` (floor spans, triangles, HUD raster IRQ, REU,
  fixed-point maths). Code that has a host twin says so in its comments (e.g. `asm/hud.S` `sfx_slew` ↔
  `sfx::slew`); `tools/test_*.py` check asm routines against reference models.
- **REU overlays.** Most code is not resident: it is linked into overlay sections with
  `#[cfg_attr(target_arch = "mos", unsafe(link_section = ".text.<name>"))]` and fetched from the REU into
  one of three windows (`target-c64/link.ld`): window 1 `$E000` (0x1800), window 2 `$A000` (0x0F00),
  window 3 `$F010`. `chopper bake` packs them into `dist/chopper.reu` from `dist/chopper.elf`. A call into
  an overlay that is not loaded at the time jumps into garbage; `tools/overlay_calls.py` checks this.
  Several overlays and resident regions have only tens of bytes free: check `tools/memmap.py` after a
  change.
- **Fixed RAM layout.** Shared state lives at fixed addresses (`src/layout.rs`, plus module constants
  such as `sfx::STATE`/`SLEW` at `$FF00+`), guarded by `const _: () = assert!(...)`. The status block at
  `$CA80` (`layout::status`) is what `tools/c64u.py status` reads. Update `tools/memmap.py`'s region list
  when you claim RAM.

## Commands

Windows host; the C64 toolchain lives in WSL (Ubuntu-24.04, rust-mos + llvm-mos via `scripts/env.sh`).

- **Host build/tests (PowerShell):** Git Bash's `/usr/bin/link` shadows MSVC's linker, so filter it out:
  `$env:PATH = ($env:PATH -split ';' | ? { $_ -notmatch 'Git\\usr\\bin' }) -join ';'; cargo test --release`
  One test: `cargo test --release <name_substring>` (all tests are in `src/tests.rs`).
- **C64 build:** `wsl -d Ubuntu-24.04 -- bash -lc "cd /mnt/c/Work/Projects/GitHub/chopper && scripts/build-target.sh"`
  → `dist/chopper.prg`, `dist/chopper.elf`. Call `wsl` from PowerShell (Git Bash mangles `/mnt` paths).
- **Bake the REU image** (after every C64 build): `target/release/chopper bake dist/chopper.reu --elf dist/chopper.elf`
- **Full gate, in order** (a stale host binary or REU shows fake mismatches):
  1. `cargo build --release` (host), C64 build, bake;
  2. `python tools/overlay_calls.py`, `python tools/memmap.py`;
  3. `python tools/emu.py --frames 6`, `--frames 6 --doubled-after 3 --full-after 5`, and
     `--frames 6 --start 12400` (a heavy scene, 155-165 triangles; catches overruns the early ticks don't.
     The war's course moves with any change to units or fights: re-pick it with `chopper frame --tick N`'s
     triangle count when it goes quiet);
  4. the asm checks touched: `tools/test_fixed.py`, `test_tri.py`, `test_poly.py`, `test_blit.py`,
     `test_hud_irq.py`, `test_audio.py`.
- **Profiling:** `python tools/profile.py --start 12400 --mode doubled [--render|--setup]`.
- **Hardware (C64U, default 192.168.66.178 or `C64U_HOST`):** `python tools/c64u.py config` (applies
  `config/chopper.cfg`), `upload-reu dist/chopper.reu`, `run dist/chopper.prg`, `status`.
  `tools/c64u_audio.py` records the C64U's audio stream (`--hrtf`/`--wav` analyse the effects' placing).
  The C64U may be shared with other sessions: ask before using it. Apply config at most once per boot
  (a second POST has hung or reset the machine); reboot first if it must change again.

## Traps

- **llvm-mos code size:** a Rust function that calls an asm `extern` drops to the soft stack and grows by
  hundreds of bytes; prefer a RAM flag the asm reads, or a (wrapped) libcall. 16-bit/i32 Rust is verbose
  on the 6502; tables usually beat arithmetic.
- **Branch range:** llvm-mc can silently mis-encode an out-of-range branch in asm; long loops use
  `beq +; jmp loop`. Zero-page operands need `mos8(...)`, or they assemble as absolute.
- **Line endings:** `.sh .py .S .ld` are `eol=lf`; keep all sources LF. Python's `write_text` on Windows
  writes CRLF: use `write_bytes(s.encode())` for scripted edits.

## Style

Comments and docs are terse prose that explain *why* and name the counterpart (`asm/hud.S` `sfx_slew`,
`layout::STATUS`), with asides in parentheses. Match that voice; keep `docs/design.md` in step with the
code. Commits: a one-line summary, then bullets of what changed and why.
